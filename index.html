Getting a new WiFi card for my HomeLab PC

Today, I got my old Lenovo laptop and took the Intel Dual Band Wireless-AC 3165NGW WiFi card out of it.

Luckily, my Dell OptiPlex has an M.2 slot that works with WiFi cards, so I could replace my external USB WiFi receiver with an M.2 one instead.

It works, and I'm happy!

Yes, I'm using WiFi right now. The main reason is that I can't run a 20-meter Ethernet cable through my home. So, as long as the PC stays on my desk for learning purposes, I'll use the WiFi card.

Thinking about replacing my old Home Server

I've been thinking about simplifying my HomeLab setup. My current home server is quite big and consumes more space and power than I'd like.

Instead of keeping a large server running 24/7, I'm considering moving my storage to an Icy Box with two HDDs and using my Dell OptiPlex Micro as the main machine for Docker and other services.

This setup would be smaller, quieter and probably much more power-efficient.

I haven't made the final decision yet, but the idea of replacing one big server with a small DAS and a Mini PC sounds cool.

This part was made for a Pull request conflict exercise

When GitHub reports a conflict in a Pull Request, it means that Git cannot automatically combine the changes from the two branches.

1. Switch to your feature branch

First, make sure you are on the branch used by your Pull Request: 

git switch feature/pullFeature

Check your current branch:

git branch

The * should be next to your feature branch.

2. Get the latest changes from GitHub

Fetch the latest information from the remote repository: 

git fetch origin

This downloads the latest changes without modifying your working files.

3. Update your local main branch

Switch to main:

git switch main

Pull the latest changes:

git pull origin main

Now your local main branch should contain the latest version from GitHub.

4. Switch back to your feature branch

git switch feature/pullFeature

5. Merge main into your feature branch

Now merge the updated main branch into your feature branch: 

git merge main

If there are conflicts, Git will stop the merge and tell you which files contain conflicts.

6. Open the conflicted files

Inside the conflicted file, Git will mark the conflicting sections like this: 

<<<<<<< HEAD
        Your changes
        =======
        Changes from main
        >>>>>>> main

Decide which version you want to keep. You can keep your changes, keep the changes from main, or combine both.

After resolving the conflict, remove the <<<<<<<, ======= and >>>>>>> conflict markers.

7. Check the status

git status

Git should show the files that were modified during the conflict.

8. Add the resolved files

Tell Git that you have resolved the conflicts: 

git add .

9. Complete the merge

git commit

Git will create a merge commit. You can keep the default commit message or edit it.

10. Push your feature branch

git push origin feature/pullFeature

GitHub will automatically update your Pull Request. If all conflicts have been resolved, the Pull Request should no longer show a conflict.

                    git fetch origin
